# v1.21.4 — 修复折行末字符丢失

在 [v1.21.3](v1.21.3.md) 基础上的**修订版**（patch）。核心交付物仍是终端编码智能体 **`springai-code-tui`**。

发布日期：2026-09-20。

## 修复内容

修复 macOS Terminal.app 中长文本折行时末字符消失的问题。例如原文 `ESC[K` 跨行后，上一行的 `E` 被擦掉，下一行只剩 `SC[K`。

根因不是折行切分漏字，而是 `InlineDisplay.println` 在正文输出之后发送 `ESC[K` 清除行尾。正文恰好写满终端时，光标处于最右列的 pending-wrap 状态，清行指令会擦掉最后一个字符。

现在改为：插入行 → 清行 → 正文 → CR/LF。清行发生在正文输出前，正文后显式回车换行，保持一次 println 对应一物理行，不缩减可用宽度，不改变折行内容。

普通文本和带样式文本共用这条修复路径。本版不新增运行时依赖、配置项或破坏性变更。

## 验证

- `mvn -pl springai-code-tui -am clean package -Pdist`：构建成功；inline-patch 75 项测试无失败，code-tui 2056 项测试无失败、无错误、跳过 13 项。编译存在既有的 `ChatModel.getDefaultOptions()` 弃用警告。
- 新增输出协议回归测试：满宽 ASCII、满宽中文、跨样式文本、续行和空行；旧实现失败，修复后通过。
- 用户使用包含修复的本地分发包，在 Terminal.app 中检查连续编号、中文、行内代码与样式混排长文本，确认不再丢字。
- `render_diff_smoke.py`：PTY 冒烟通过，覆盖静止零输出、ASCII/CJK 输入、边框修复及修复结束后恢复静止。
- `mvn -pl springai-code-tui javadoc:javadoc`：通过，无 Javadoc 错误或警告。
