# v1.21.5 — 视觉链路计量校准 + DeepSeek 模型改名适配

发布日期：2026-09-21。

本版一个主题收敛三块修复：**图片额度与 token 计量按真机实测全面校准**（四家
provider 口径全部实测，替换文档推算）、**DeepSeek 2026-09-21 模型合并改名适配**
（旧配置自动迁移，不丢视觉能力）、以及两项底层修复（流取消连接泄漏、JUL 日志
打乱输入框）。

## 修复内容

### 1 图片 token 计量：四家口径全部真机实测

原实现用 Anthropic 口径（`宽×高/750`）处理**所有** provider，方向性错误两头都占：
对 DeepSeek 高估 3.6 倍（6000 的每请求上限实际只放得下 3 张图），对聚合网关的
OpenAI 通路低估 2–9.6 倍（预算判定过松，请求发出去才发现超支）。现按 provider
分家（新增 `ImageProfile`），四家口径全部真机实测：

| provider | 口径 | 来源 |
| --- | --- | --- |
| DeepSeek | 下限 226、约 `226 + 像素/2400`、封顶 1024；长边 1300 | 真机实测 |
| 智谱 GLM | `min(6086, max(18, ⌈宽/28⌉ × ⌈高/28⌉))`；长边 1568 | 真机实测（glm-4.6v，官方未公布，实测拟合） |
| OpenAI 通路 | `⌈宽/32⌉ × ⌈高/32⌉ × 1.2`，按原始像素；长边 2048 | 真机实测（聚合网关，三款模型一致；**官方端点需重测**） |
| Anthropic / 通义 | 官方公式不变 | 官方文档 |

端到端验证（同一张 2442×1146 真实截图）：DeepSeek 估算 1538 → 556（真机约
1000 量级内）；OpenAI 发出 2048×961、估算 2381、实测 2381（零误差）；智谱
发出 1568×736、估算 1512、实测 1458（差 3.7%）。

配套：`MAX_REQUEST_TOKENS` 6000 → 16000（旧值按高估 3.6 倍的数字定的），
`CODETUI_VISION_REQUEST_TOKENS` 可覆盖；换 provider 后缩放缓存不会误命中。

### 2 图片投递节奏：额度不再被重发吃光

此前图片引用只要在当轮范围内，**每轮请求都被重新兑现**——第 1 轮工具产出的截图
在此后 11 轮仍被重发，把回合额度耗尽，模型真正需要看图时 Read 也拿不到。两处修复：

- **首次推一次**（高水位线）：用户图在回合首轮推一次、工具图在产出轮推一次；
  模型后来 Read 老图仍能拿到（引用下标 ≥ 高水位线照样兑现）。实测同场景自动
  重发 12 张·次 → 1 张·次。
- **用户图与工具图独立额度**：共用额度时工具循环会挤掉用户图（实测 2 张用户图
  第 7 轮被掐）。现拆成两套计数器：工具图 12 张·次、用户图 36 张·次，各有界。
  新增 `CODETUI_VISION_USER_TURN_BUDGET`；原 `CODETUI_VISION_TURN_BUDGET`
  现只管工具图。
- 额度耗尽时引用如实写 `turn_budget_exhausted`，不再对模型说「Read 一次就能看」
  这句假话（工具侧与出站侧共用同一 `VisionBudget` 实例才能感知）。

代价说明：模型需要用老图时多一次 Read 往返；首次推送那轮没看到不自动补发。

### 3 DeepSeek 模型改名：flash 与视觉模型合并

官方 2026-09-21 把 `deepseek-v4-flash`（纯文本）与 `deepseek-v4-flash-vision-exp`
（视觉实验）**合并**为单一 `deepseek-flash`（图像理解 = 支持，且已是思考模型——
默认返回 `reasoning_content`，可关闭）。旧名仍可调用（实测三个名字带图返回同一
token 数，确为同一后端别名）。

- DeepSeek 内置清单 3 项 → 2 项（`deepseek-v4-pro` + `deepseek-flash`）；
- `model.json` 存有旧名的用户**读取时自动升级**为新名——不迁移会静默回退到
  `deepseek-v4-pro`（不支持图片），表现为「图片功能突然没了」；
- 视觉名单放行新名与两个旧名；聚合网关（OpenCode Go）清单同步改名。
- token 口径与改名前逐字一致（800×600→349、1200×900→694），`ImageProfile`
  无需重标定。

### 4 底层修复

- **流取消不释放连接**：升级 Spring AI 2.0.0 → 2.0.1。旧版把 SDK 异步流转
  Reactor 时未接取消事件，上层超时/取消后底层连接不释放（探针实测 active=1，
  需等服务端 EOF）。2.0.1 实测取消后 active=0。配套：SDK client 版本对齐
  （openai 4.49.0 / anthropic 2.52.0）、显式声明 httpclient5（缺失会使
  DeepSeek 阻塞路径 NoClassDefFoundError）、删除千问 SSE 归一化补丁（上游
  2.0.1 已按 index 合并分片，补丁冗余）。
- **JUL 日志打乱输入框**：OkHttp 走 `java.util.logging`，告警直接写 stderr
  打乱 TUI 输入框。现启动时移除 JUL 控制台 handler 并桥接 SLF4J 落文件，
  保留告警与异常栈。

## 验证

- `mvn -pl springai-code-tui -am clean test`：inline-patch 75 项、code-tui
  2080 项测试无失败、无错误（跳过 13 项）。
- 新增测试：`ImageProfileTest`（四家口径实测断言，含迁移与封顶/地板）、
  `VisionPushOnceTest`（高水位线首次推一次）、`VisionTurnBudgetTest`
  （双额度独立性）、`CodeTuiApplicationLoggingTest`（隔离 JVM 验证 JUL 桥接）。
- 真机实测：DeepSeek/智谱/OpenAI 通路端到端 token 对照（见上表）；DeepSeek
  新名读出测试图的字母与背景色；改名后 token 口径与旧实测逐字一致。
