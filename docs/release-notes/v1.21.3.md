# springai-agentdemo v1.21.3

在 [v1.21.2](v1.21.2.md) 基础上的**修订版**（patch）。核心交付物仍是终端编码智能体 **`springai-code-tui`**。

本版两项改动，都指向长会话/弱网下的稳定性：一是把三层重试的退避序列整体拉长、并开始采信服务端的 `Retry-After` 头；二是修掉自动压缩偶发的 Anthropic 400（孤儿 `tool_result`）。

**下载物：** 两个自包含运行包 `springai-code-tui-1.21.3-dist.tar.gz`（macOS / Linux 首选）/ `springai-code-tui-1.21.3-dist.zip`（Windows 首选），解压即用、无需构建，内容与惯例一致：启动脚本（`bin/`）+ 主 jar + 全部运行期依赖（`lib/`）+ 配置示例 + 使用指南 + `LICENSE`/`NOTICE`/`README`。运行时界面版本标识为 **`v1.21.3`**。SHA-256 校验和见文末「发布前验证」。

> 完整功能全景与安全声明见 [v1.3.0 发布说明](v1.3.0.md) 与 [v1.0.0 发布说明](v1.0.0.md)；本文只列出相对 v1.21.2 的变化。

## 改进：重试退避升级 1s·2s·4s·8s·16s·30s（总尝试 7）+ 采信服务端 `Retry-After`

原来的退避序列是 500ms×2ⁿ、封顶 4s、最多重试 4 次（总尝试 5）。网关坏窗口通常以十秒计，4s 封顶意味着最后几跳还没等到服务端恢复就把尝试用光了，弱网/限流下容易直接把回合判死。

本版把退避序列整体拉长为 **1s×2ⁿ、封顶 30s**（即 `1s·2s·4s·8s·16s·30s`），三层重试全部对齐**总尝试 7**：

- L1 流式重试 `L1_RETRIES=6`；
- 子 agent `MAX_ATTEMPTS=7`；
- L2 回合级续跑 `L2_RESUMES=4`。

同时新增对 **`Retry-After` 头的采信**：遇到 429/529 且服务端在 `Retry-After` 里明示了等待时长（`delta-seconds` 与 HTTP-date 两种格式都认），就听服务端的（它更懂何时恢复），但仍受 60s 封顶约束防畸形大值；无头则退化为纯指数退避。两条异常链都覆盖——`WebClientResponseException`（Spring 侧）与 `OpenAIServiceException`（openai-java SDK 系，智谱/Qwen/OpenAI 都走它）。

实现上把退避与延迟计算收敛到 `RetryPolicy` 作为**唯一真相源**：新增 `nextDelayMs`/`retryAfterMs`（Retry-After 归一化）与 `backoffRetry`（L1/L2 共用的 reactive `Retry` 工厂，替代此前分散的 `Retry.backoff` 与 `CodingAgent.resumeBackoffMs`）；子 agent 阻塞式 `Thread.sleep` 退避与 L1/L2 的 reactive 退避共用同一个测试压缩钩子（`scaledDelayMsForTest`），耗尽类用例得以秒过而上报给 UI 的 `backoffMs` 仍是真值。界面上「传输/续跑」文案的区分改用 `maxAttempts==7` 判定——L1 显示 `(x/7·传输)`，L2 显示 `(x/4·续跑)`。

## 修复：自动压缩边界只在用户回合起点切开，杜绝孤儿 `tool_result` 触发 400

自动压缩后偶发 Anthropic 400「unexpected tool_use_id found in tool_result blocks」：归档/保留的切割边界落在了 `tool_use` 与其 `tool_result` 之间——`tool_use` 被归档、`tool_result` 却被留在保留窗口，成了孤儿块，发给模型即报 400。

根因：`BoundedSummarizationCompactionStrategy` 的边界回退只判 `isRootEvent()`，但这个方法在 `spring-ai-session-management` 里仅表示「不在子 agent 分支」（`branch == null`）——单 agent 会话里对每条事件恒为 `true`，于是那圈「回退到安全边界」的循环彻底沦为空操作，切割点想落哪落哪。

修法：抽出 `isTurnStart()`，要求同时**是 root 且为 USER 消息**，与框架自带的 `CompactionUtils.snapToTurnStart` 口径一致；事件数分支与 token 预算分支两处统一改用它。新增 `BoundedSummarizationSplitBoundaryTest` 复现并锁住该回归。

## 测试

- **重试升级**：`RetryPolicyTest` 更新退避序列断言至 `1s·2s·4s·8s·16s·30s`，新增 `Retry-After` 采信（delta-seconds / HTTP-date / 畸形 fail-open）用例；`RetryingChatModelTest`/`RetryingStreamChatModelTest`/`ConversationStateRetryTest`/`CodingAgentTurnResumeTest` 同步更新尝试数与 `2/7·传输` 文案。`SubagentRunnerBackgroundTest` 失败路径此前走满真实退避（累计约 61s）会超时，改用 `@BeforeEach` 装 `compressBackoff` 复用新压缩钩子。
- **压缩边界修复**：新增 `BoundedSummarizationSplitBoundaryTest`，钉住切割点必须落在用户回合起点、tool_use/tool_result 不被拆散。
- 全模块单测（`springai-tamboui-inline-patch` 30 余个、`springai-code-tui` 全量）与 `background_smoke.py`（后台子 agent 五场景）均通过。改动按 revert-confirm-red / restore-confirm-green 变异测试纪律逐一验证。

## 升级说明

**无配置变更，无破坏性变更。** 直接替换运行包即可。升级时请先退出旧进程，再替换文件并重新启动（`jar` 走 Java 类加载，替换文件后必须重启才生效）。

- 弱网/限流下的重试更有耐心：单次退避最长 30s、总尝试 7 次，且遇到 429/529 会优先按服务端 `Retry-After` 明示的时长等待（封顶 60s）。界面重试提示相应显示 `(x/7·传输)` / `(x/4·续跑)`。
- 长会话触发自动压缩时，不再偶发 Anthropic 400「unexpected tool_use_id」——压缩切割点现在只落在用户回合起点，不会再把工具调用与其结果拆散。
